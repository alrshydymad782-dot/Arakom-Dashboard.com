# أراكم (Arakom) — نظام إدارة بوابات المرور الذكية

نظام لإدارة البوابات بالتعرف الآلي على لوحات السيارات (ANPR). كل بوابة فيها **كاميرا دخول + كاميرا خروج + ريليه**.
عندما تقرأ الكاميرا لوحة سيارة مسموح لها، **تُفتح البوابة تلقائياً** خلال أجزاء من الثانية.

| الرابط | لمن |
|---|---|
| `admin.arakom.sa` | إدارة أراكم: العملاء، الاشتراكات، الكاميرات، مراقبة النظام، مدفوعات سلة |
| `app.arakom.sa` | مدير المجمع: الحركة المباشرة، فتح البوابة يدوياً، السيارات المسموح لها، التقارير |

## كيف يعمل الفتح التلقائي

بُني الربط على ملف المصنع **MQTT Communication Protocol V4.x**:

```
الكاميرا                          Mosquitto                       خادم أراكم
   │ 1) camera_register  ──────► /serverAll ─────────────────────► يسجل الكاميرا ويحفظ subtopic
   │ ◄──────────────────────────────────────── camera_register_rsp
   │ 2) mqtt_herat (كل 30 ث)  ─────────────────────────────────────► الكاميرا متصلة
   │ 3) result (اللوحة + inout) ► arakom/gates/{gate_id}/readings ─► تحقق:
   │                                                                  ✓ المجمع نشط؟
   │                                                                  ✓ الاشتراك ساري؟
   │                                                                  ✓ اللوحة في القائمة وغير محظورة؟
   │ ◄──────────────────────────────────────── result_rsp
   │ ◄── iooutput {ionum:1, action:"on"}  (الكاميرا تشغّل الريليه فيُفتح الذراع)
   │     + arakom/gates/{gate_id}/command  {"action":"OPEN_BARRIER","relay_id":1}
   │                                                                  ثم يسجل العملية ويرسلها للوحات فوراً
```

- عند الرفض لا يُرسل أي أمر، ويُسجل السبب: غير مسجل، محظور، الاشتراك منتهٍ، المجمع موقوف...
- القراءات المتأخرة (`type: offline`) المخزنة أثناء انقطاع الإنترنت تُسجل فقط بدون فتح.
- الرسائل المكررة من الكاميرا لا تُسجل مرتين.

### لماذا أمران للفتح؟
- كاميرات المصنع **لا تفهم** صيغة `{"action":"OPEN_BARRIER"}`، بل تفهم أمر المصنع `iooutput` (القسم 3.2.3 من الملف).
  لذلك يرسل الخادم `iooutput` لموضوع الكاميرا نفسها، والكاميرا تشغّل الريليه المتصل بها.
- ويرسل أيضاً `{"action":"OPEN_BARRIER","relay_id":1}` على `arakom/gates/{gate_id}/command` كما طلبت،
  لأي جهاز ريليه منفصل (مثل ريليه WiFi/ESP32) يستمع لأراكم مباشرة.
- إن كان الريليه موصولاً بالكاميرا فقط ولا تريد الأمر الثاني، فلا ضرر منه. وإن أردت إيقاف `iooutput` اجعل `MQTT_SEND_CAMERA_IO=0`.

## التثبيت على السيرفر

**المتطلبات:**
- سيرفر VPS بنظام Ubuntu، ويكفي 2 معالج و4GB رام.
- النطاقان `admin.arakom.sa` و`app.arakom.sa` يشيران إلى عنوان IP السيرفر (سجل A).
- المنافذ مفتوحة في الجدار الناري: `80` و`443` و`1883`.

```bash
git clone <رابط المستودع> arakom && cd arakom
bash deploy/setup.sh
```

السكربت يثبت Docker، ويولّد كل كلمات المرور، وينشئ حسابات MQTT، ويشغل كل شيء.
بيانات الدخول تُحفظ في `deploy/CREDENTIALS.txt`: احفظها في مكان آمن ثم احذف الملف.

### تشغيل أول بوابة
1. ادخل `admin.arakom.sa` ← **المجمعات** ← **مجمع جديد**: أدخل الاسم والجوال والاشتراك وحساب مدير المجمع.
2. من صفحة المجمع أضف **بوابة**، وأعطها رمزاً إنجليزياً مثل `yasmin-main`. هذا هو `{gate_id}`.
3. في صفحة إعدادات **كل كاميرا** (من متصفح الكمبيوتر على شبكة الكاميرا)، فعّل MQTT واضبط:
   - الخادم: عنوان IP السيرفر، والمنفذ: `1883`
   - المستخدم: `camera`، وكلمة المرور من `CREDENTIALS.txt`
4. تظهر الكاميرا تلقائياً في **الكاميرات والبوابات**. اضغط **ربط** واختر البوابة ونوعها (دخول أو خروج).
5. من قائمة **أوامر** اختر **ضبط مواضيع أراكم**. بعدها تنشر الكاميرا على `arakom/gates/{gate_id}/readings` وترفع صورة اللوحة مع كل قراءة.
6. يضيف مدير المجمع سيارات السكان من `app.arakom.sa`، يدوياً أو باستيراد ملف Excel/CSV.

### ربط متجر سلة
1. في **الباقات ومدفوعات سلة** أنشئ باقة، واكتب فيها رمز المنتج (SKU) نفسه الموجود في متجر سلة.
2. في لوحة شركاء سلة أضف ويب هوك على الرابط `https://app.arakom.sa/api/webhooks/salla`:
   - الأحداث: `order.created` و`order.status.updated` و`order.payment.updated`
   - استراتيجية الأمان: Signature
3. ضع مفتاح التوقيع في `SALLA_WEBHOOK_SECRET` داخل `.env`، ثم نفّذ: `docker compose up -d`.
4. عند الدفع يتعرف النظام على المجمع من **الجوال أو البريد** المسجل:
   - إن كان **التجديد التلقائي** مفعلاً للمجمع، يُمدد الاشتراك فوراً.
   - وإلا تظهر الدفعة في لوحة الإدارة بانتظار موافقتك.
   - الدفعات التي لا يُعرف صاحبها تظهر كذلك لتربطها يدوياً.

## التجربة على جهازك (بدون كاميرات حقيقية)

تحتاج: Node.js 20 أو أحدث، وPostgreSQL.

```bash
# قاعدة البيانات
createdb arakom   # أو: CREATE DATABASE arakom;

# الخادم
cd backend && npm install
npm run broker:dev                       # نافذة 1: وسيط MQTT تجريبي
ADMIN_PASSWORD=Admin12345 npm run dev    # نافذة 2: الخادم على المنفذ 4000
npm run simulate                         # نافذة 3: كاميرتا دخول وخروج وهميتان

# الواجهة
cd ../frontend && npm install && npm run dev   # http://localhost:5173
```

- لوحة المجمع على `http://localhost:5173`، ولوحة الإدارة على `http://localhost:5173/admin`.
- الاختبارات: `cd backend && npm test`.

## ملاحظات مهمة

- **ترتيب أحرف اللوحة:** على اللوحة السعودية يقع كل حرف إنجليزي تحت مقابله العربي.
  لذلك يُقرأ العربي «ا ب ح» بالإنجليزي «J B A». النظام يحوّل الصيغتين لمفتاح واحد ويعرض معاينة للوحة عند الإضافة.
  **جرّب ذلك بسيارة حقيقية بعد تركيب أول كاميرا**، وتأكد أن اللوحة التي يقرؤها النظام تطابق المسجلة في القائمة.
- **التسجيل عند الاتصال فقط:** الكاميرا ترسل رسالة التسجيل مرة واحدة عند اتصالها.
  لذلك يستخدم الخادم جلسة MQTT دائمة، فإن أُعيد تشغيله لا تضيع رسائله، ويحفظ موضوع كل كاميرا في قاعدة البيانات.
- **تصدير PDF:** يتم من المتصفح (طباعة ← حفظ PDF)، حتى يظهر الخط العربي بشكل صحيح.
- **الصور** تُحفظ 60 يوماً **والسجلات** 180 يوماً، ويمكن تغيير المدتين في `.env`.
- **رمز المنطقة الزمنية** في أمر ضبط وقت الكاميرا معكوس الإشارة في ملف المصنع، لذلك رمز السعودية (UTC+3) هو `15`.
